M6.6 so far: what is left open

The choices made while building parts 1 to 3 of M6.6 that are not yet confirmed, and the gaps those parts left, each with where it is to be dealt with. Written 2026-10-19. The same items are in gui-plan.md (the M6.6 notes, D162 to D166 and the Open list); the design is in value-lists.html.

Choices to confirm

D162The type of items.itemType (part 1)

A new built-in type, Type: a type as the program runs. items.itemType, map.keyType and map.valueType give one (any for a collection made without its type). It prints as written (List<int>), two are == when they are the same type, and x is Type tests for one.

Your choice

D163How the C++ functions' results are checked (part 1)

By a test setting, not on every call. ASTRA_CHECK_NATIVE_RESULTS=1 compiles a check after every call of an external function against its declaration; the suite passes with it, and each checkpoint would run it beside the GC and thread stress settings. The C++ is fixed code, so the suite proves its declarations once, and later parts can then trust them while the program runs. The other way, a check on every call, costs every call of the C++.

Your choice

D164What the check changed in the standard library (part 1)

  • The coerce functions give one of their numbers as it was, so float.coerceIn(Number, Number) and the like now say Number, with forms for all ints and all floats that say int and float. (2.5.coerceIn(0, 1) is the int 1.)
  • A type parameter that the object a call is made on says nothing of (a Map written without type arguments) is unknown, not taken from the arguments: data.get(key, "missing") is no longer typed string? there.
  • Deque.toList builds a List<T> rather than casting its List<T?>, and Set == gives false for a set of other things rather than failing at a cast, now that casts are checked in full.
Your choice

D165The rules of a value type, as built (part 2)

  • value Point(val x : int, val y : int) needs a header whose entries are all fields. It is a data class: printing, ==, copy, coming apart.
  • It may implement interfaces, extends no class, and no class extends it.
  • A field is given its value in the header, where it is declared in the body (one declared there with none is an error), or in the type's init; never again. p.x = 4, and x += 1 in a method, are compile errors saying to make a changed copy, until changing through a place (part 4).
  • === on a value type is a compile error, as a value has no identity; through any it compares contents.
  • A value type cannot hold itself except where that field may be null; the checker reports it.
  • Every core may read a value, since it never changes.
Your choice

JadeJade's geometry as value types (part 2)

Jade's Point, Dimension, Insets and Rectangle are still classes. Jade changes them where they are (setSize, translate, setLocation), so they can become values only with changing through a place (part 4), and that changes what code sharing them means: Jade's API, which is yours to decide. Measured on a copy of Jade's layout, values were 10% faster and a Sizes of three Dimensions one allocation of 88 bytes instead of four of 336.

Your choice

D166Lists of values, as built (part 3)

  • A list is packed when it is given its type (by its literal, by what it is declared as, or at the call of a C++ function that made it): List<int>, List<float>, List<bool>, a value type's list, and the nullable ones of those.
  • Putting in a value the list was not made to hold is an error where it is put in (cannot put a value of type string in a List<int>), which an unchecked cast through List<any> used to allow.
  • A copy of a list (toList, slice, subList, reversed, + of two of one type) keeps its type and how it is kept.
  • sortBy and sortByDescending, for every list, call the selector once per item rather than twice per comparison (a million items sorted in 70 to 130 ms instead of 1.5 s). A selector with side effects sees fewer calls.
Your choice

SizeThe largest value type (from value-lists.html)

Decided "any size, up to 64 KB". Offered on 2026-10-18 and not yet answered: "any size, with a copy on read past 64 KB". The limit comes only from the 16-bit offset in a reference into a list item, and only fields kept in place count towards it.
